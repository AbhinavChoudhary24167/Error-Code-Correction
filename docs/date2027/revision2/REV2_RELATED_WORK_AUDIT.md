# Revision 2 focused related-work audit

Audit date: 2026-08-25

## Scope and search boundary

This audit updates the historical DATE 2027 audit with a focused search of primary publisher/proceedings records and author or institutional copies, emphasizing 2018--2026 work in DATE, DAC, VTS, IEEE journals, and arXiv, plus foundational papers required to delimit the contribution. Search concepts included memory ECC hardware, SECDED/Hsiao/BCH architecture, synthesis/PPA, post-layout or post-route evaluation, pipeline/combinational comparison, physical-design variability, seed sensitivity, and implementation-aware selection.

The audit is focused rather than exhaustive. A failure to locate a paper is not evidence that none exists. In particular, this work makes **no priority claim** and does not claim that ECC/PPA co-evaluation, hardware-conscious codes, or multiple architectures for one coding task are new.

## Positioning outcome

The defensible contribution is the controlled conjunction of:

1. an explicit separation of code semantics, RTL architecture, and routed physical identity;
2. correctness or exact-equivalence qualification before physical measurement;
3. a common, pinned RTL-to-route policy with explicit unavailable/infeasible points;
4. a prospective matched-seed sensitivity sweep for multiple correctness-qualified implementations;
5. equal-useful-work activity-based energy only at timing-feasible target-clock points.

No paper in this focused set was found to combine all five controls for the same evaluated memory-ECC set. This is an audit inference, not a universal literature-absence claim.

## Explicit audit observations

- ECC PPA comparison is established prior art; Revision 2 claims only a particular identity-preserving experiment.
- Same-task architecture comparison is established in BCH/checker literature; Revision 2’s exact-equivalent SECDED pair is narrower and physically controlled.
- Cross-layer correction/cost co-design is established in STT-MRAM and memory-system work; Revision 2 does not claim novelty for that broad idea.
- The recent BCH literature shows large architecture sensitivity, so the paper must say “the evaluated BCH realization” at every physical conclusion.
- No audited work reported OpenROAD placement/routing outcomes over matched, predeclared seeds for an exact-equivalent SECDED microarchitecture pair. Because the search is not exhaustive, the manuscript phrases this as the design of the present experiment, not as a first-of-kind claim.
- None of the audited works makes a five-seed sweep a population estimate. Revision 2 likewise treats it only as a controlled heuristic-sensitivity envelope.

## Manuscript changes required by this audit

1. Replace any broad novelty language with the five-control conjunction above.
2. Cite hardware-conscious Hsiao/checker, low-delay SEC/SECDED, stronger-correction hardware, system-level cross-layer, recent adaptive ECC, and recent BCH-architecture work.
3. State explicitly that implementation identity is the paper’s experimental unit; code labels do not pool PPA.
4. Scope BCH to one qualified realization and describe Hsiao PPA as belonging to the new algorithmic RTL identity connected to the historical semantics by exact equivalence.
5. Avoid “first,” “only,” “unexplored,” and family-wide dominance claims.
